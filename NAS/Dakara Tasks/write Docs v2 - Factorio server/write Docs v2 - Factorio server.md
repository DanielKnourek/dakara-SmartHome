## Requirements
- TrueNAS version TrueNAS-SCALE-25.10.1 and above (or generic Docker with Compose).
- app-pool setup (`apps` user/group with UID/GID `568`).
- ZFS dataset `ssd-data1/factorio-server` created and configured with appropriate permissions.

## Installation

### 1. Creating ZFS Dataset
Create the ZFS dataset on `ssd-data1` pool and configure the correct ownership and permissions:

```sh
sudo zfs create \
  -o acltype=posixacl \
  -o xattr=sa \
  -o atime=off \
  -o compression=lz4 \
  "ssd-data1/factorio-server"

# Set ownership and permissions for the "apps" user and group (568:568)
sudo install -d -m 775 -o apps -g apps \
  /mnt/ssd-data1/factorio-server
```

### 2. Compose File Configuration
Make sure the `deployment.yaml` file exists at `/mnt/ssd-data1/factorio-server/deployment.yaml` and contains the configuration for Factorio (Experimental 2.1.7).

```sh
sudo touch /mnt/ssd-data1/factorio-server/deployment.yaml
sudo chmod 660 /mnt/ssd-data1/factorio-server/deployment.yaml

# Open and paste configuration
sudo vim /mnt/ssd-data1/factorio-server/deployment.yaml
```

### 3. Deploying to TrueNAS SCALE
Deploy the application and register its custom web interface icon using the deployment helper utility:

```sh
sudo ~/deploy_app.py factorio-server --file /mnt/ssd-data1/factorio-server/deployment.yaml --icon https://media.sys.truenas.net/apps/factorio/icons/icon.png
```

### 4. Configuring Server Settings
To customize your server name, description, visibility, or password:

1. Locate the `server-settings.json` file. Note that this file is automatically generated in your config folder once the container has started up for the first time:
   ```sh
   # Path: /mnt/ssd-data1/factorio-server/config/server-settings.json
   sudo vim /mnt/ssd-data1/factorio-server/config/server-settings.json
   ```
2. Update the `name` property to your preferred name (e.g. `"DeathMarathon on Dakara"`):
   ```json
   "name": "DeathMarathon on Dakara",
   ```
3. Restart the Docker container to apply the changes:
   ```sh
   sudo docker restart factorio
   ```

* **Auto-Pause (Default behavior)**: By default, the Factorio server is configured to automatically pause when no players are present. This prevents the factory from consuming resources or being attacked while everyone is offline. This behavior is controlled in `server-settings.json`:
  ```json
  "auto_pause": true
  ```
  Set this to `false` if you want the game time/simulation to keep running when the server is empty.

## Configuration Details
The server runs using `factoriotools/factorio:latest-rootless` (configured for Space Age DLC 2.1.7).

- **Game Port:** `25520` (UDP)
- **RCON Port:** `25521` (TCP)
- **Data Path:** `/mnt/ssd-data1/factorio-server` (mapped to `/factorio` in the container)
- **User/Group:** Runs as UID `568` / GID `568` (`apps:apps`)
- **Saves:** For details on specifying and loading saves (using `LOAD_LATEST_SAVE` and `SAVE_NAME`), see the [Saves / Specify a save directly](https://hub.docker.com/r/factoriotools/factorio?tag=latest-rootless#specify-a-save-directly-01779-2) chapter on Docker Hub.
